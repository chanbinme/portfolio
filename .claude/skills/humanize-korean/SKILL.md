# humanize-korean 스킬

한국어 문장의 AI 티를 걷어내고 자연스럽고 개인적인 톤으로 윤문합니다.

## 사용 목적

포트폴리오, 이력서, 블로그 등 개인 문서에서:
- 딱딱한 표현을 자연스러운 말투로
- 과도하게 완벽한 표현을 사람다운 톤으로
- 반복되는 구조를 다양하게

## 핵심 원칙

1. **사실과 수치는 절대 변경하지 않기**
   - 숫자, 기술명, 회사명 등은 그대로 유지
   - 성능 지표, 기간, 버전 모두 보존

2. **개인의 목소리 유지하기**
   - 자신의 가치관과 스타일이 드러나도록
   - "~해야 한다"는 식의 당위성보다 실제 경험 중심

3. **전문성 손상 없기**
   - 기술 용어는 정확하게 유지
   - 복잡한 개념은 명확하게

## 개선 패턴

### 보수적 AI 톤 → 사람다운 톤

| 피해야 할 표현 | 개선 방향 |
|---|---|
| "~했습니다" (반복) | "~하고", "~해서" (문맥에 맞게 변화) |
| "~하려 합니다" | "~합니다", "~하고 있습니다" |
| "~할 수 있도록" (거치적거림) | "~할 수 있게" 또는 직접 표현 |
| "사전에 ~" (중복) | "~" (중복 제거) |
| "~을/를 미리 ~" | "~을/를 ~" (중복 제거) |
| "~을/를 통해" (과다) | "~로", "~와 함께" (다양화) |

### 문장 구조 개선

- 긴 문장을 짧은 문장 여러 개로 분해
- 나열이 많으면 "-", "·"로 시각적 개선
- 불필요한 접속사 제거

### 톤 개선 예시

❌ "거래의 일관성을 보장하기 위해 모듈 안은 Spring Event, 모듈 간은 RabbitMQ 메시지 큐 기반 이벤트 아키텍처를 도입했습니다."

✅ "거래 일관성을 보장하기 위해 모듈 안은 Spring Event, 모듈 간은 RabbitMQ로 이벤트 흐름을 설계했습니다."

---

❌ "리팩토링과 배포에 자신감을 가지며 개발합니다."

✅ "리팩토링과 배포를 두려워하지 않고 개발합니다."

---

❌ "파트너 통보·계좌 반환·집계가 함께 움직이도록 구조화했습니다."

✅ "파트너 통보·계좌 반환·집계가 한 곳 수정으로 함께 연동되도록 개선했습니다."

## 사용 방법

```bash
# 파일 목록 확인
/humanize-korean src/content/profile.json src/content/experiences.json

# 또는 단일 파일
/humanize-korean src/content/profile.json
```

## 작업 흐름

1. 각 문장을 읽으며 "이게 사람답게 들리나?"를 자문
2. AI 티가 나는 부분 표시
3. 사실/수치 확인
4. 자연스러운 표현으로 대체
5. 최종 검증

## 주의사항

- JSON 구조는 유지 (파일명, 필드명 등)
- 기술 용어는 정확하게
- 사용자가 직접 작성한 내용은 최대한 존중
- 의도가 명확하지 않으면 원문 유지
